# 再帰的情報家系図および Satori ZKP 仕様書

**ドキュメントID:** `TH-SPEC-03` | **レイヤー:** Tier 1（公開プロトコル仕様）

## 1. 概要とプライバシー・真正性の二律背反

高い保証水準が求められるデータエコシステムは、**「検証可能性（Verifiability）」** と **「機密性（Confidentiality）」** の間に根本的な緊張関係を抱えている。

* 下流の消費者（AI学習パイプライン、保険数理引受機関、査読者）は、データが三重浄化監査（TFA）を通過し、汚染されていない一次情報源に由来することの暗号学的証明を要求する。
* 上流の生産者（R&D研究所、企業、エッジテレメトリ運用者）は、独自の実験パラメータ、生データセット、または事業上の企業秘密（トレードシークレット）を外部に開示することができない。

この二律背反を解決するため、**Trust-Hash Protocol** は永続的な系譜追跡のための **再帰的 Merkle-DAG（有向非巡回グラフ）** と、ペイロードおよびメタデータのプライバシーを保護するための **Satori ZKP（ゼロ知識証明回路）** および **時間遅延ミキシング（Temporal Chaffing）** を組み合わせている。

## 2. 再帰的情報家系図（Recursive Data Lineage / Merkle-DAG）

検証を通過したすべてのデータセットまたはテレメトリ成果物には、追記専用（Append-Only）かつコンテンツアドレス指定の **Merkle-DAG** 内のノードが割り当てられる。金融残高を追跡する線形ブロックチェーンとは異なり、Trust-Hash の家系図グラフは **因果的および熱力学的な派生関係** を追跡する。

```
      [一次センサー / 実験ラン A]         [一次学術文献 / コーパス B]
           (Tier 1: Anchor)                    (Tier 2: Verified)
                  │                                    │
                  └─────────────────┬──────────────────┘
                                    ▼
                     [派生 R&D 失敗解析ログ C]
                       • 親ハッシュ: [Hash(A), Hash(B)]
                       • TFA 監査スコア: 0.942
                       • ZKP シールド: 有効 (Enabled)
                                    │
                                    ▼
                     [蒸留済み V-Fuel データセット D]
                       • 推移的純度: 100%
                       • 家系図深度 (Lineage Depth): 2
```

### 2.1 推移的純度と遡及的スラッシング（Retroactive Slashing）

1. **親ハッシュバインディング：** 新たなデータセット $D$ が上流の入力群 $\{P_1, P_2, \dots, P_n\}$ から合成・蒸留・派生された場合、その `Trust-Hash Certificate` はすべての親入力の `certificate_id` に対して暗号学的にコミットしなければならない。
2. **汚染の伝播（Contamination Propagation）：** 上流の祖先ノード $P_k$ が後から無効化された場合――検証ノードのスラッシング（カナリアトラップへの誤承認など）や事後的な異常監査によるものかを問わず――その信頼度低下は DAG の下流へと決定論的に伝播する。
3. **自動隔離（Automated Quarantine）：** 下流の検証クエリ（`GET /v1/lineage/{id}/purity`）は、`synthetic_contamination_ratio`（合成汚染率）が消費者の定義した安全閾値を超過したあらゆる子孫ノードに即座にフラグを立て、汚染データが AI の事前学習ランに流入するのを阻止する。

## 3. Satori ZKP 回路アーキテクチャ

**Satori ZKP** により、組織は非公開の生データセット $X$ の中身を検証ネットワークや公開台帳へ一切開示することなく、$X$ がすべての TFA 述語（条件）を満たしていることを数学的に証明できる。

### 3.1 証明者・検証者関係（Prover-Verifier Relation）

$X$ を非公開の生ペイロード（独自の化学合成ログや臨床テレメトリ等）、$W_{\text{phys}}$ を TEE 署名済みのハードウェアテレメトリ（消費電力、熱拡散、RF 痕跡）、$\pi$ を生成されたゼロ知識証明とする。

証明回路 $\mathcal{R}_{\text{TFA}}$ は以下の命題を強制する：

$$
\exists (X, W_{\text{phys}}) \quad \text{s.t.} \quad \begin{cases} \text{Commit}(X, r) = C_X \\ \text{VerifyTEE}(W_{\text{phys}}, \text{pk}_{\text{hw}}) = 1 \\ \Phi(NNS(X)) \ge \theta_{\text{nns}} \\ \Delta I(PT(X)) \ge \theta_{\text{pt}} \\ \mathcal{C}(W_{\text{phys}}) \ge \theta_{\text{ao}} \end{cases}
$$

* **公開入力（Public Inputs）：** コミットメントハッシュ $C_X$、ハードウェアルート公開鍵 $\text{pk}_{\text{hw}}$、保証ティア分類、および親 Merkle-DAG ルート。
* **非公開証人（Private Witnesses）：** 生ペイロード $X$、ブラインディング係数 $r$、中間 R&D 状態遷移履歴、および生のマルチモーダルセンサー波形 $W_{\text{phys}}$。

*（※注記：動的な判定閾値* $\theta_{\text{nns}}, \theta_{\text{pt}}, \theta_{\text{ao}}$ *は、`[Foundry Core / Proprietary Calibration]` からのブラインド・コミットメント更新を通じて注入されるため、回路の検証ロジックは静的な公開定数から切り離された状態に保たれる。）*

## 4. メタデータのサイドチャネル防衛：時間遅延ミキシング

生ペイロードがゼロ知識証明によって遮蔽されていても、個別の証明書コミットメントをリアルタイムで公開すると、R&D の開発ペース、計算資源の消費スパイク、および組織間のグラフ構造相関といった機密性の高い運用メタデータが漏洩するリスクがある。

サイドチャネル推測を無力化するため、Trust-Hash は **時間遅延ミキシング（Temporal Chaffing）およびゼロ知識ロールアップ** を実装する：

```
[組織 A 証明リクエスト] ──┐
[組織 B 証明リクエスト] ──┼──► [ランダム化時間ウィンドウバッファ] ──► [ZK-Rollup 集約器] ──► [公開 Merkle-DAG]
[ダミーチャフ証明]      ──┘         (タイムスタンプ同期を切断)          (単一バッチルート)
```

1. **時間ウィンドウバッファリング：** 受信した証明提出リクエストは、即座に台帳へ書き込まれず、ランダム化されたエポック時間ウィンドウ内に一時保持される。
2. **チャフ混入（Chaff Injection）：** ロールアップ集約器は、真正な証明リクエストに対して暗号学的に識別不能な重みゼロのダミー証明（チャフ）を混合し、ネットワークトラフィック量を平準化する。
3. **バッチ状態コミットメント：** 単一の再帰的 ZK-Rollup 証明によって混合バッチ全体を公開家系図台帳へ一括コミットし、上流の親参照と下流の企業活動との間のタイムスタンプ相関を完全に切断する。

## 5. 帰属計算およびロイヤリティ分配との互換性

Trust-Hash は特定のネイティブ暗号資産の使用を強制しないが、Merkle-DAG 構造は祖先ノード全体にわたる決定論的な暗号学的帰属重み（アトリビューション）を提供する。外部のライセンシング、データ市場、および保険数理決済システムは、この DAG を走査することで、検証済みの一次データ貢献者に対してロイヤリティを比例配分することができる。
